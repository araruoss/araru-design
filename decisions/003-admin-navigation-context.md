# ADR 003: Admin uses a separate navigation context

- Status: Accepted
- Problem: Operational destinations should not overload the primary library navigation.
- Decision: Admin has an explicit context and navigation model, denser information presentation and a clear return to the library.
- Reason: Administrative tasks have different frequency, risk and information density.
- Alternatives: mix admin destinations into primary navigation, use an unstructured settings page.
- Platform impact: Expanded clients use an admin sidebar; compact clients use a drawer or navigation stack.
